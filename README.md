# BleWeightScale — 小米 S200 体重秤 Android 客户端

通过蓝牙低功耗（BLE）扫描接收小米 S200 体重秤（型号 MJTZC02YM，蓝牙标识 `yunmai.scales.ms106`）
广播的体重数据，解密后在界面实时显示，并保存称重历史。

**无需配对、无需连接。** 秤只在称重时唤醒蓝牙并开始广播，打开应用站上秤即可。

## 快速开始

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

首次运行需要授予蓝牙权限（Android 11 及以下为定位权限）。

### 必须配置 bindkey

小米从 MiBeacon v4 起对广播里的体重数据做了 AES-128-CCM 加密，**没有 bindkey 就无法解密**，
应用只能显示"无法解析体重数据"。bindkey 由小米云端按设备下发，应用无法自行推导，需要导出一次：

1. 在电脑上运行任意一个"小米云 token 提取"脚本，例如 GitHub 上的
   [`PiotrMachowski/Xiaomi-cloud-tokens-extractor`](https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor)。
2. 用米家账号登录（建议使用只绑定了体重秤的小号，脚本需要账号密码）。
3. 在输出的设备列表中找到体重秤，复制其 **BLE 密钥 / bindkey / beaconkey**，
   是一串 32 位十六进制字符。
4. 在应用的「设置」页粘贴保存。

bindkey 只保存在本机 SharedPreferences 中，不会上传到任何服务器。

### 可选：设备 MAC

解密需要设备的身份地址来构造 CCM nonce，而加密报文本身不带 MAC，只能依赖 Android
上报的地址。如果一直提示"解密失败"，可以在「设置」页的**设备 MAC（可选）**填入体重秤的
MAC（形如 `AA:BB:CC:DD:EE:FF`，与 bindkey 在同一个导出结果里）。应用会把帧内 MAC、
手填 MAC、扫描地址依次作为候选试解——AES-CCM 带 4 字节认证标签，错误的候选会被拒绝，
不会解出错误体重。

## 支持的协议

| 协议 | 服务 UUID | 说明 |
| --- | --- | --- |
| MiBeacon v4/v5 | `0xFE95` | S200 / S400 / S800，**AES-CCM 加密**，需 bindkey |
| GATT Weight Scale | `0x181D` | 初代小米体重秤，明文，10 字节 |
| GATT Body Composition | `0x181B` | 小米体脂秤，明文，13 字节，含阻抗 |

> 注意：**S200（MJTZC02YM）没有体脂电极**，因此不会产生阻抗或体脂数据。
> 应用里显示的阻抗字段只在 `0x181B` / S400 / S800 上才有值。

## S200 数据格式

广播以服务数据形式出现在 Xiaomi 服务 `0000fe95-0000-1000-8000-00805f9b34fb` 下。
以下是服务数据负载（不含 AD 结构头）的布局：

```
偏移   长度  字段
0..1    2   帧控制（小端）  位 12..15 版本 / 位 6 含对象 / 位 5 含 capability
                            位 4 含 MAC / 位 3 已加密 / 位 10..11 认证方式
2..3    2   产品 ID（小端）   S200 = 0x45C9 / 0x4C04 / 0x4DCB
4       1   帧计数器
5..     6   设备 MAC（逆序）  仅当帧控制位 4 置位
        ?   capability 字节   仅当帧控制位 5 置位（其位 5 置位时再多一个 IO 字节）
        ?   对象区            仅当帧控制位 6 置位
        3   扩展计数器 }      仅当帧控制位位 3（已加密）置位
        4   MIC 认证标签 }
```

对象区在加密时用绑定的 bindkey 做 AES-128-CCM 解密，参数为：

- **nonce** = `MAC 逆序(6) || 负载[2..5)(3) || 扩展计数器(3)` — 共 13 字节
- **AAD** = `0x11`
- **tag** = 4 字节

解密后是 `类型(2) | 长度(1) | 值(长度)` 的对象序列。S200 的体重对象是 `0x4E16`：

```
值偏移  长度  字段
0       1   profile id（用户槽位）
1..4    4   体重 = 千克 × 100（小端 uint32；值为 0 表示人已下秤）
5..8    4   Unix 时间戳（小端 uint32）
```

秤还会周期性发送一个不含对象的"空闲广播"（帧控制位 6 为 0），其中带设备 MAC，
可用于校准 Android 上报的地址。

### 实现说明

- **AES-CCM 是自行实现的**（`AesCcm.kt`），只做解密方向，底层用 `AES/ECB/NoPadding`。
  Android 各 API 级别的 JCA provider 对 CCM 的支持并不一致，自己实现可以保证
  API 26–36 行为完全一致，也便于在 JVM 单元测试中验证。
- **nonce 用的是帧内 MAC**（有的话），否则用扫描到的设备地址。Android 在某些机型上
  会返回随机化地址，因此应用会缓存帧内 MAC 并在解密失败时重试。

`app/src/test/java/dev/sopho/scale/MiBeaconParserTest.kt` 使用 `xiaomi-ble` 项目
（Home Assistant 所用的参考实现）测试套件中公开的真实报文，其中 S200 用例带有
bindkey 与期望体重。测试通过即同时验证了帧结构、CCM nonce 构造与体重换算：

```bash
./gradlew :app:testDebugUnitTest
```

目前 24 个用例全部通过：其中 19 个验证蓝牙协议（包括真实 S200 报文解密得到 62.25 kg），
另外 5 个验证旧历史兼容迁移、多人归属与去重、并发写入、BMI 分级和趋势统计。

## 多人称重、BMI 与报告

- 在首页「切换成员 → 管理家庭成员」添加姓名、身高；可选填写此成员的**秤侧用户编号**。
  编号与设备 MAC 一起绑定才能自动认领 S200 的体重广播。未绑定的读数进入「未认领数据」，
  可在历史页手动认领或改派。**当前查看的成员不等于实际站秤的人**，应用不会仅凭当前选中者归属读数。
- 旧 `weights.json` 历史原样保留，为每条补稳定 ID；由于无法证明原来显示的“用户槽位”属于谁，
  旧数据继续归在「未认领数据」。删除成员后其历史也回到未认领，且不会误删别人的记录。
- 按人员查看单次称重报告：体重、BMI 分类、参考目标体重、控制差额和日常建议；趋势可选近 7、30、90 天、半年和自定义日期，展示曲线、最小/最大/平均、区间变化、记录对比。
- **计算口径**：成人 BMI = 体重 kg / 身高 m²；<18.5 偏瘦、18.5–23.9 标准、24–27.9 超重、≥28 肥胖。
  参考目标体重 = 22 × 身高 m²；目标差额 = 目标−当前。米家截图的标准体重可能采用其他算法，因此数值
  不必完全一致。未设身高或不适用成人 BMI（儿童、孕期等）时隐藏 BMI 和体重控制建议；这些内容仅供参考，
  不能代替医疗建议。
- 人员和历史保存在应用私有目录的 `people.json` / `weights.json`，使用原子写入和串行更新。
  bindkey、MAC 只保存在本机偏好设置中，**不会写入源码**。

## 项目结构

```
app/src/main/java/dev/sopho/scale/
├── ble/
│   ├── AesCcm.kt            AES-128-CCM 解密（RFC 3610）
│   ├── MiBeaconParser.kt    MiBeacon v4/v5 帧解析与对象解码
│   ├── LegacyScaleParser.kt 0x181D / 0x181B 明文格式
│   ├── ScaleScanner.kt      BLE 扫描封装，解码后发布事件与原始报文日志
│   └── Models.kt / Hex.kt
├── data/
│   ├── SettingsStore.kt      bindkey 与偏好设置
│   ├── PersonRepository.kt  本地人员、身高与秤侧编号
│   ├── WeightRepository.kt  稳定 ID 的历史记录与旧数据迁移
│   └── WeightMetrics.kt     BMI、建议与趋势计算
├── ui/                       称重 / 报告 / 趋势 / 成员 / 设置 / 日志
└── MainActivity.kt          权限申请与导航
```

## 界面

- **称重** — 按成员显示最新体重、BMI、参考目标、体重趋势；保留扫描与解密状态
- **报告** — 单次称重的 BMI 分级、目标差额、成人健康管理建议及免责声明
- **记录** — 按成员/未认领筛选，区间折线图、统计、记录认领或改派、两次数据对比
- **家庭成员** — 添加、编辑和切换成员，绑定秤侧用户编号，儿童/孕期可关闭成人 BMI 参考
- **设置** — bindkey 输入、MAC、自动记录开关
- **日志** — 原始蓝牙报文（十六进制）与解码结果，用于排查协议问题

称重结束后自动记录：优先以秤发出的"已下秤"（体重为 0）报文作为结束标志，
若固件不发送该报文，则以 8 秒静默超时兜底。30 秒内相同体重的重复广播会自动去重。

## 已知限制

- 仅被动接收广播，不建立 GATT 连接。若某台秤的固件不广播含体重对象的报文
  （社区报告过 `xiaomi.scales.ms113` 的部分固件如此），本应用无法读取数据，
  需要走 GATT `0xFE95` 登录 + 加密数据通道的方案，本应用未实现。
- 应用需在前台才能扫描（扫描绑定在 Activity 生命周期上），不提供后台常驻服务。
- 小米体脂秤的体脂率算法未实现，只显示秤直接给出的阻抗值。
